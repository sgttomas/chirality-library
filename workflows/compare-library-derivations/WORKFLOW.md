# Compare Library derivations

Use this method when an undertaking selects comparison of project documents
adapted from Library sources. The undertaking chooses the trigger, files,
target basis and decision participants. This method sets no session-start or
release-adoption schedule.

The result is an understood comparison with justified dispositions, authorized
edits or proposals, and explicit remaining uncertainty. A difference needs
interpretation against the project's purpose and authority.

## Establish the basis

Identify the project files and their actual revision or working content, the
target Library edition or exact candidate revision, and any prior reconciled
edition. Read the applicable project authority and relevant local constraints.
The project's Agent 0 owns local decisions and integration within its authority.
An authorized coordinator or contributor may inspect and discuss; read-only
access grants no right to edit. The assignment sets permitted writes, and
reserved decisions go to the owner.

Map each file to its actual adaptation source. Check
[`metadata.upstream`](../../docs/document-metadata.md#library-derivation)
where present against source and project evidence. Where absent or doubtful,
use adoption changes or other relevant evidence; a matching name or nearby
checkout is insufficient. Adapted project `AGENTS.md`, `init/init-prompt.md`
and `loop/LOOP_INIT.md` map to the relevant sections of
[project-entry](../project-setup/resources/project-entry.md), not Library
`AGENTS.md`. Adapted workflows map to their actual Library source and needed
resources. Roles and methods read directly from the selected Library are
resolved at that basis; do not copy them merely to compare them.

Keep product packaging and separately pinned assets outside this comparison.
Their source maps and adoption contracts retain their own authority.

## Compare and discuss

Where the prior reconciled edition is available, compare its Library source,
the current project adaptation, and the target Library source. Read upstream
changes alongside local differences. Follow corresponding subjects where a
template distributes content across several project files. Examine meaning,
authority, links and required resources as well as wording. Verify source moves
or replacements; a text diff locates changes but cannot decide their meaning.

Without the prior baseline, a two-way comparison can establish a fresh basis
if the mapping is justified and all applicable target content is examined and
dispositioned. State that historical change attribution is unavailable. If the
mapping or target content is unavailable or uncertain, bound what can be
compared, identify the missing input and continue unaffected work. Failed
retrieval or an empty diff does not establish equivalence.

Discuss consequential differences with their evidence, effect and project
reason. Distinguish deliberate local adaptation, applicable upstream change,
possible reusable improvement and unresolved meaning or evidence. These may
overlap. Agree what remains local, what changes locally, what merits an
upstream proposal and what remains unresolved. Retain useful adaptations and
project authority rather than making files match.

An upstream candidate needs a shared purpose beyond one project's arrangement.
Give Library Agent 0 the bounded problem, source basis, proposed change and
consequences through the authorized coordination route. Keep private material
out of public proposals. Library content approval, release and each project's
adoption remain separate acts; a candidate commissions none of them.
Apply only authorized edits through the owning repository's process. Decisions
edit the text they govern; use existing review or Work locations for findings
that need continued attention.

## Verify and return

Inspect changed documents together for preserved authority, local meaning,
working links and needed resources. Validate changed metadata and run the
project's proportionate checks. Distinguish source inspection and walkthroughs
from observed execution.

Add or advance `metadata.upstream` only after the whole adapted document is
reconciled against the applicable source content of the recorded published
edition. Consequential differences need justified dispositions and required
changes must be present and checked. Deliberately retained adaptations permit
advancement; unfinished required reconciliation or unresolved applicability does
not. Candidate revisions support discussion, but cannot stand for an unpublished
edition: check the final published source before recording it. Project-wide
Library adoption does not advance every document's field. Leave an existing
field unchanged after partial comparison; omit it if no justified pair exists.

Return the compared files and exact bases, material differences and reasons,
dispositions, edits or proposals, checks and remaining decisions in the
conversation or existing PR/Work location. No separate report or registry is
required. If interrupted or incomplete, identify the usable result, unexamined
bounds, missing inputs, unchanged reconciliation claims, next action and actor.
Keep at most one replaceable recovery note where ordinary work and review
records cannot support continuation. A partial return establishes neither
reconciliation nor adoption.
