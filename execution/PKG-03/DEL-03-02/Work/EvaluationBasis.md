maintenance as the pilot and relevant local agent records with raw records kept
private. The accepted amendment/setup is integrated by PR #1798 at
`8b8bd691d1e680749612c02c207dd276e7c5f982`. This Work describes a bounded first
software increment, not product acceptance, full qualification or a Library release.
The [ScopeOfWork](../ScopeOfWork.md) and [accepted decomposition](../../../_Decomposition/_LATEST_ACCEPTED.md)

Use [the tool guide](../../../../tools/undertaking_evaluation/README.md) for the

The [evaluation workflow](../../../../workflows/evaluate-repository-change/WORKFLOW.md)

Python 3.10+ and Git are required; the implementation uses the standard library.

The first route reads selected immutable Git commits and literal repository paths,
with optional explicitly selected Codex desktop JSONL per-response usage records.
It writes a fresh private JSON/HTML report outside Git working trees. It does not
collect working/untracked state, launch agents, execute supplied checks, decide
whether a claim follows from evidence, select a winner or confer acceptance.

## Implemented meaning and examination

Repository state change is the primary evaluative subject. The software binds
source object identities and supplied assessment evidence; the selected question
and examination give those observations their meaning. A source diff is not
behavior verification or a valuation of the change. Reports identify unknowns,
partial observation and the difference between supplied assessment and tool checks.

The Codex adapter consumes only selected-turn `token_usage_record` per-response
usage. It deduplicates response IDs, rejects conflicting duplicates and ignores
cumulative summaries and raw message/tool bodies. It does not infer full worker
coverage, retry meaning, elapsed undertaking duration, actual spending or human
attention. Token categories may overlap; no invented combined total is produced.

Comparisons bind case identity, question, starting source, paths, conditions,
examination basis, environment and resource declarations. Matching metadata is
not proof of experimental control. Input reports are validated for schema and
internal consistency; they are not authenticated against deliberate fabrication.
Private relative input locators and hashes support report-to-case-to-evidence
recovery without copying operational text into the report.

Independent code/privacy scrutiny found and repaired malformed-report handling,
malformed turn identity, Git replacement/environment source confusion,
changed-question comparability and hash-only evidence discovery. Thirty focused
unit tests pass, including adverse input, identity, path/output, deduplication,
comparison and HTML-escaping cases. Code review does not qualify all host records
or establish the substantive truth of a supplied assessment. Output precautions
are not a sandbox against hostile concurrent processes.

## Actual private pilot and its finding

Two actual isolated TASK trials used the same selected public Library source at
`2fbdc1ec3563690c5820be6b01cfdd56c7bdf813`, the same instruction-repair objective,
allowed files, practical written budget and inherited host configuration. One
brief supplied the goal/source set; the other additionally identified relevant
source sections. Both fresh agent contexts excluded this implementation
conversation. The host's existing dispatch/return mechanism executed the trials;
this tool did not supply a new runtime. Written limits were procedural, not
claimed host-enforced resource caps.

Each trial changed the four allowed scope-of-work instruction files and retained
the three reference files in its captured source set. Actual per-response records
were selected by the known trial session/turn relationship and frozen privately.
The final tool imported them and generated inspection and comparison reports;
input discovery locators and their hashes were checked against retained inputs.
Operational records, private Git copies, assessment material and reports remain
outside this public repository. Public tests use handcrafted synthetic records.
No operational counts, message bodies, session IDs or private paths are copied here.

An independent reviewer examined anonymized source results. Its initial categorical
ranking assumed amendment registers/checkpoints were necessarily legacy control
files. Examination against the actual supplied basis exposed that assumption:
the governing scope-change contract was absent. The reviewer withdrew the ranking
and returned conditional findings. Both results address lifecycle dependence;
full amendment-authority compatibility remains unestablished from the supplied
case. The original criteria and outputs were preserved; no rerun sought a winner.

The actual reports therefore carry unknown overall outcome and partial effort
coverage. The comparison establishes matching declared basis and inspectable
observations, not an efficiency effect, causal result or preferred method. The
useful return is a case-framing finding: a future authority-preservation case
must bind the governing amendment contract. That would be a new case basis,
not retroactive regrading of these trials.

observed browser. It does not inspect the private pilot reports, qualify every
possible path/claim length, establish accessibility conformance or measure reader
comprehension. Fixture reports and browser scratch are temporary examination
material, not publication assets or new operational evidence.
