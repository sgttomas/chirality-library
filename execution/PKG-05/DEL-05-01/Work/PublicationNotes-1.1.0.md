# Chirality library 1.1.0 — publication notes

The owner selected **Chirality library 1.1.0**, tag name `library-v1.1.0`.
These are preparation notes, not a published release or a claim of full R18/A9
acceptance. The preparation PR identifies the checked source candidate, archive
and checksum. Publication requires the owner's separate decision; the eventual
release must identify its exact source commit and attached archive SHA-256.

The comparison basis is published **1.0.2**, source
`59433388627773f008f550481c4159514f43c7e5`. The functional and instructional
changes below are integrated through `e57e0b783cc50a354819bc83bd38bd86a063ad77`;
this preparation reconciles their current descriptions and adds bounded report
rendering evidence. Earlier editions retain their bytes and original standing.

  adds DEL-03-02 and extends DEL-04-02 under accepted PRD R18/A9. Acceptance of

  imposing retired lifecycle files on that route. Retained legacy contracts keep
  their applicability; the selected project's actual authority still governs

- **Courses for sustained and delegated agent work.** [PR #1795](https://github.com/sgttomas/chirality/pull/1795)

  reading editions align with these changes. The Northbank case records and

- **Book subtitle.** [PR #1796](https://github.com/sgttomas/chirality/pull/1796)
  adopts the author's title, *Chirality in Practice: Extending Human Capability
  with Agents*, in the Markdown and rendered book. The argument and reflective

## Use and dependencies

Obtain the complete source archive of the eventual named release, or clone its
exact tag/commit. Preserve relative paths, resources, [MIT notice](../../../../LICENSE.md)
and applicable component notices. Start with the
[consumer route](../../../../README.md#obtain-and-use-the-library), then the
selected holding's own guide. Reading the book, courses and workflows requires
no Git or private operational records. Agents can read their maintained Markdown.

The new evaluation CLI needs Python 3.10+ and Git, using only the Python standard
library. Repository inspection requires actual Git commit objects: an extracted
source archive alone does not contain the Git history being examined. Supply a
separate authorized Git repository, or use a clone. Workflow selection through
the existing resolver retains its own documented dependencies and host limits.

`inspect` and `compare` create private `report.json` and `report.html` files in a
new directory outside Git working trees; its parent must already exist. Inputs,
raw records, assessments and derived reports remain private unless separately
examined and authorized for disclosure. Preserve the original inputs while their
findings need to remain inspectable. The public source and tests contain no
private pilot records and ordinary use needs no undisclosed sibling checkout.

## Qualification and adoption limits

The supported first record adapter reads explicitly selected Codex desktop JSONL
per-response `token_usage_record` events. It does not establish support for all
host versions, full-session coverage, monetary cost, elapsed work or human
attention. Committed-file observations do not establish behavior or value.
Working-tree capture, a trial runner, automated semantic evaluation and automatic
method adoption are not supplied. Output precautions are not a sandbox against
hostile concurrent processes.

The first actual private Library-maintenance comparison was inconclusive: its
case omitted a governing amendment contract, and an independent assessor withdrew
a categorical ranking. The useful finding was the missing case basis, not an
efficiency gain. Full R18/A9 fulfillment remains unestablished. Representative
HTML reports have subsequently been examined in a browser using labelled cases
over public source; this is representation evidence, not renewed examination of
the private pilot or a reader-comprehension study. See
[the owning evaluation basis](../../../PKG-03/DEL-03-02/Work/EvaluationBasis.md).

These additions require no automatic migration or consumer adoption. Compare the
exact source you use with the proposed release through the existing
[change-inspection route](../../../../README.md#inspect-changes-before-adopting-them).
Select only applicable changes under your project's authority. Root's grants,
acceptance and release do not transfer to App, SWBPIPE or another consumer.
Historical sources remain recoverable through Git, earlier releases and the
recovery guide (`sgttomas/chirality:projects/FROZEN.md`, private archive). Publication and any downstream
notification delivery remain separate from this preparation.
